# UX

How the interface looks and behaves: file tree, notes, editor, terminal tabs.

## Input
- Keyboard only. No pointer.

## Display
- Text-only for now. Fonts and markdown rendering are nice to have later.

## Structure
- Tabs, switched by keyboard.
- Each tab starts in a file tree and can switch to a terminal. Any CLI can run there (Claude Code, others); no tool is blocked.
- Lands on a UI, not a bare terminal, so non-terminal users can navigate.

## MVP
- File tree navigation and file editing.

## Must have
- File tree navigation.

## Nice to have
- Links and backlinks.
- Markdown rendering (possible later addon).
- Fonts.
- Search bar over notes (from the original brief).

## Notes backend
- Plain markdown files in a folder, compatible with an Obsidian vault.
- Sync is toggleable (Obsidian Headless, Syncthing, git); see 01-requirements.md. Notion and Google Docs are later, one-way at most.

## Editor
- Default is modeless and as close to Word as practical: type to insert, Ctrl shortcuts for commands. Shortcuts customisable.
- Vim keys as an optional profile, not the default.

## Code editing
- Required, not an afterthought. Line numbers, syntax highlighting, format on save or on shortcut.
- Run shortcut: runs the current file or a set command in a new tmux tab and keeps the output visible.
- Optional later: language-server diagnostics.

## Out of scope
- Browser. Dropped. Captive-portal Wi-Fi is avoided by using a phone hotspot.
